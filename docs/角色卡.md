# Character Card V3（兼容 V2 导入）

需要 AstrBot `>=4.29.3,<5`。打开 WebUI → 插件管理 → 浮生绘卷的插件页面 `studio`。页面跟随 WebUI 明暗主题，支持桌面和窄屏，无需额外服务；图片处理使用 AstrBot 已有的 aiohttp / Pillow 依赖。

## 统一角色库

打开或刷新角色库时，插件将可访问的 AstrBot 现有人格自动转为 V3 卡片，包括系统默认人格。后续在 AstrBot 新建的人格也会在下次刷新时纳入。已有绑定卡片的直接复用；已归档或主动解除绑定的原记录不会被重复转换。

转换保留原 `persona_id`、核心记录身份、文件夹、排序及会话引用，不写入核心人格。卡片名称默认取 `persona_id`；完整提示词放入 `system_prompt`，不自动拆出描述、性格或场景。`begin_dialogs` 显示为 `mes_example`，完整原始人格保存在 `data.extensions.astrbot_persona_studio.persona_import.persona` 中，工具、技能和错误回复同时映射到卡片 options。

原提示词未编辑时按字面保留，不额外加入角色名称或展开其中的角色卡宏；原示例未编辑时继续使用核心预设对话，避免重复注入。编辑这两个字段后，对应字段按角色卡规则编译；恢复初始快照可恢复原运行内容。空预设的 `null` 与 `[]` 在运行中等价，扩展中仍保留原始值。

首次转换保存一份初始快照，角色版本留空，不从核心日期推断作者日期。原归属保持不变；未设归属的由管理员管理，原人工锁继续阻止修改。现有人格的纳入不受新建数量上限阻挡；后续创建仍检查配额。无法转换的记录会在页面说明原因，其余卡片仍正常显示。

## 使用流程

1. 导入 V2 / V3 JSON 或 PNG，统一转换并保存为 V3，保留角色版本、原图及未知字段；可以新建独立卡，也可以完整替换当前卡。
2. 新建角色卡固定使用 V3，默认创建独立的 AstrBot 人格，ID 由角色名称和卡片 ID 后缀构成。也可仅存卡片，稍后创建并绑定人格。不会认领或覆盖已有同名人格。
3. 编辑角色、对话、指令或 AstrBot 专用工具/技能配置，预览使用后端实际编译结果；保存后同步运行副本。
4. 需要定版时手动修改 `data.character_version`，保存后新增这一版本的完整快照。
5. 通过 AstrBot 的人格选择入口或 `persona_switch` 使用页面显示的绑定人格 ID。只从下一次构造的聊天请求生效。

导出仅包含已保存内容，可选 JSON / PNG，固定使用 V3（`spec: chara_card_v3`、`spec_version: 3.0`），不提供 V2 导出。PNG 仅写入 `ccv3` 角色卡数据块，优先使用角色卡图片作为底图（包括导入的原始 PNG），未设置时使用解析后的头像；两者都没有时使用内置占位图。原始 PNG 中的 `chara-ext-asset_:` 内嵌资源会一并保留。没有角色卡底图且头像读取失败时，PNG 导出会说明原因，JSON 导出仍可使用。未知字段、扩展、世界书和资源声明完整保留。

## 页面添加图片与头像

在角色卡的“图片与头像”分区，可分别添加或替换角色卡图片、头像，支持 PNG / JPEG / WebP：

1. 选择文件后显示待保存预览，可撤销本次选择；不会立即修改角色卡或丢弃其他编辑。
2. “角色卡图片”用于 PNG 导出的底图，保留原尺寸并转为 PNG。更换底图会保留原 PNG 中的内嵌资源，避免已有 `__asset:` 头像引用失效。
3. “头像”可独立上传，保持比例缩放到最长边不超过 512 像素，转为 PNG；也可点“使用角色卡图片”，让头像跟随底图。上传的独立头像写入 V3 `assets` 的 `icon/main` Data URL，JSON / PNG 导出均可携带；JSON 不包含独立的底图像素。
4. 点击“保存并同步”时，图片与文字在同一次卡片保存中生效。普通替换不增加快照；同时改变角色版本时，底图引用和头像内容随完整快照留档，恢复后一起还原。

上传图片仅用于选图，不读取其中的角色卡文字，先校验真实图片内容、修正旋转方向并清除元数据；动态图片使用首帧。上传暂存绑定当前 WebUI 用户，有效期 30 分钟，过期后需重新选择。保存仍检查当前 revision、人工锁和绑定人格权限。文件最大 20 MiB，转换后的 PNG 同样受此限制；头像随 JSON 一起受角色卡总大小 2 MiB 限制。

## 主头像与资源

- `data.assets` 未提供时按 V3 默认使用 `icon/main` 的 `ccdefault:`，即导入的原始 PNG；显式 `[]` 或没有 icon 时不显示头像，不回退到原图。
- 多个 icon 中必须有且只有一个 `name: main`。兼容只有一个 icon 但名称不是 main 的卡片；存在歧义或缺少 URI 时提示原因，不猜测图片。
- 支持 `ccdefault:`、Base64 Data URL、公网 HTTPS，以及 PNG 的 `__asset:path` 引用（`chara-ext-asset_:{path}` 文本块）。校验实际图片内容，支持 PNG / JPEG / WebP，忽略不准确的 `ext` 和 MIME 声明。
- 首次打开卡片或导出 PNG 时解析头像。HTTPS 只允许无凭据的 443 端口公网地址，逐次检查 DNS 和重定向目标，不携带 WebUI 凭据、Cookie 或代理环境配置；总超时 15 秒，最多三次重定向，限制文件大小和像素数。
- 解析成功后按内容哈希存储图片，SQLite 持久保存资源键到图片的映射。同一 URI 首次成功解析后固定复用，修改 URI 才选择另一资源；内嵌资源的键还包含原始 PNG 引用。快照恢复继续使用相同映射，不受远端同 URL 后续换图影响。尚未成功读取的远程资源无法冻结其当时内容；读取失败不会写入缓存，下次打开可重试。
- 保存、导入替换和快照恢复都会刷新页面头像；图片失败不影响文本保存或人格同步，头像位置显示原因。原图与已缓存资源不自动删除，备份时需要同时保留数据库和整个 `assets/`。
- 本版仍只导入 JSON / PNG，不导入 CHARX 压缩包。`embeded://` 依赖包内文件，保留 URI 并提示暂不支持；HTTP、本地文件等其他 URI 同样保留，不读取。其他 icon、背景、表情等资源暂不渲染。

## 字段与运行内容

| 角色卡字段 | AstrBot 中的处理 |
| --- | --- |
| `name` | 角色名称进入提示词；`persona_id` 是独立稳定的绑定标识，改名不改变绑定 |
| `description`、`personality`、`scenario` | 编译为 `system_prompt` 的独立段落 |
| `system_prompt` | 角色指令；空值使用默认指令；`{{original}}` 引用默认指令 |
| `mes_example` | 解析 `<START>` 和 `{{user}}:` / `{{char}}:`，以临时示例消息插入；无法解析时保留原文在提示词中 |
| `first_mes`、`alternate_greetings` | 无实际历史的新对话使用选定的一条作为临时助手背景，不主动发送 |
| V3 `group_only_greetings` | 群聊优先使用该列表中同一序号的开场白；越界不注入 |
| `post_history_instructions` | 作为本轮用户输入末尾的临时文本内容，保持用户原始输入与已存历史不变 |
| `creator`、`creator_notes`、`tags`、角色版本、日期 | 用于卡片管理和导出，不主动进入提示词 |
| V3 `assets` | 解析主头像用于页面；未设置底图时也用于 PNG 导出，原始声明保留，其他资源暂不使用 |
| `character_book` | 角色卡内置世界书，按本轮消息与历史触发，临时注入角色设定前或后；规则与限制见下节 |
| `extensions`、未知字段 | 原样保留，不执行酒馆脚本或正则；世界书中本插件的运行设置除外 |
| 无对应标准字段 | `tools`、`skills`、`custom_error_message` 存在卡片的 AstrBot 专用 options 中 |

新建或文件导入卡片的核心 `begin_dialogs` 保持为空；标准示例可能包含非成对消息，改由请求钩子注入，避免核心的成对预设格式改变示例含义。示例、开场白和历史后补充都带核心临时标记，不进入永久会话历史。仅对实际选中的、成功同步且运行内容未发生外部修改的绑定卡片启用适配。

支持文本宏 `{{char}}`、`{{user}}`、`{{original}}`，用户名来自真实当前消息；其余宏保留原文，不执行表达式。这不是完整的 SillyTavern 提示词组装器，不保证所有酒馆预设的上下文顺序和模型表现一致。

`tools` / `skills`：`null` 表示全部可用，`[]` 表示全部禁用，名称列表表示指定范围；新设置的名称需已注册；从现有人格保留且未修改的工具/技能名称允许暂时不可用。自定义错误回复留空清除。工具/技能未在卡片中修改时，同步会保留核心端独立调整的配置；卡片选项发生变化后，以该次明确修改覆盖对应选项。

## 世界书（第一版）

在角色工作台打开“世界书”页签，左侧添加、选择条目，右侧编辑名称、正文与触发规则。关键词使用可移除标签，按 Enter 添加，也支持顿号、中文逗号、英文逗号或换行分隔；尚未确认的关键词在保存和切换条目时一起收录。条目新增、修改、停用或移除都属于草稿，点击“保存并同步”后参与真实聊天。普通保存不新增快照，定版、恢复和导出继续保留完整世界书及未知扩展。

- **关键词触发**：在当前用户消息及最近 N 条用户／助手历史消息中，按文字包含关系匹配任一主关键词；默认不区分大小写，可逐条开启。可选“辅助触发条件”，要求另命中任一辅助关键词。不同消息之间不拼接成一个词。
- **始终生效**：无需关键词，每轮都尝试注入；仍受启用状态与字符预算约束。停用单条或整本世界书后，相应内容不注入。
- **扫描范围**：默认最近 4 条历史消息，可设 0～50；0 表示只扫描当前消息。临时示例、开场白、系统提示、工具结果与标记为临时的消息／文本块不参与匹配。扫描内容最多 32000 字符，超出时保留最新内容；不扫描世界书条目正文，不做递归激活。
- **注入位置与顺序**：支持 `before_char`（角色设定前）和 `after_char`（角色设定后，默认）。同一位置按 `insertion_order` 从小到大排列，默认 100；相同时按原条目列表顺序。内容支持 `{{char}}`、`{{user}}` 文本替换。
- **字符预算**：默认 4000，范围 0～16000，0 表示不注入。预算包含世界书标题、正文及条目之间的换行，按宏展开后的内容计数；两个位置共用一个预算。不使用模型 tokenizer，不保证等于导入卡片中的 `token_budget`。预算不足时先保留 `priority` 较高的条目，再按注入顺序与列表顺序选择；条目整条跳过，不截断正文。
- **触发预览**：在页签下方输入测试消息，可附加从旧到新的历史消息和测试用户名；直接使用当前未保存草稿。预览与真实请求共用同一匹配器，显示每条的命中、未命中、停用、正文为空、超出预算或未支持原因，并展示实际注入文本。不会新建卡片、调用模型或写入聊天历史。

世界书使用卡片原有 `data.character_book`，无需新建数据库表。书级扫描范围保存在 `scan_depth`；本插件的整书开关与字符预算保存在 `character_book.extensions.astrbot_persona_studio` 的 `enabled` / `max_chars`，缺省分别为 `true` / `4000`。标准条目字段包括 `keys`、`secondary_keys`、`content`、`enabled`、`constant`、`selective`、`case_sensitive`、`priority`、`insertion_order`、`position`。导入条目缺少 `enabled` 时默认启用，缺少正文或字段格式无效时跳过该条，其余条目继续运行。最多运行前 500 条，每种关键词列表最多 64 项、每项最多 256 字符；更多数据仍随卡片原样保存。

第一版仅支持角色卡自带的世界书，不提供全局共享书、独立世界书文件导入或完整酒馆引擎。递归扫描和 token 预算会显示兼容说明；带正则关键词、V3 装饰器、概率、冷却、延迟、向量、分组选择、逐条扫描范围或其他已识别但未支持规则的条目保留原数据并跳过，预览明确说明原因。未识别扩展仅保留，不执行。可在“更多设置 → 原始数据”调整导入的高级规则。

世界书仅对实际选中且同步正常的绑定角色卡启用。冲突、解除绑定或归档时不注入；人工锁定只阻止编辑，不影响已保存角色正常运行。每轮重新计算，不缓存上轮命中状态，也不改写 AstrBot 已保存的人格提示词或永久会话历史。

## 版本和时间

- 创建或首次导入生成初始快照，此后仅角色版本字符串实际变化时生成修改后的完整快照。允许任意版本字符串，不比较版本大小，也不自动递增。
- 格式转换不会修改 `character_version`，也不会单独触发定版快照。已有 V2 卡片读取时按 V3 提供，下次保存写为 V3；历史快照原文与校验值保留，恢复旧 V2 快照时转为 V3。
- 快照包含完整角色卡、AstrBot options 和原图引用，长期保留。恢复直接替换为快照内容，不额外保存当前草稿，不自动更改角色版本或作者日期。
- `revision` 是内部并发整数，保存、绑定、锁定等操作会变更；不是角色版本，也不等于快照数量。同步状态变化独立于内容 revision。
- 插件卡片 `created_at` / `updated_at` 是本地记录首次保存 / 最近编辑时间；核心 Persona 的同名字段描述核心运行副本的生命周期。
- V3 `creation_date` / `modification_date` 是作者文档的 Unix 秒时间。导入和导入替换保留原值；本地修改 V3 内容时更新 `modification_date`，原始 JSON 明确填写不同值时尊重该值。选项修改与同步不改作者日期。V2 导入转换时不补造作者日期。

## 存储与同步

```text
data/plugin_data/astrbot_plugin_persona_studio/
├── studio.sqlite3       # 权限/普通备份，以及 cards/card_snapshots/card_imports/card_persona_sources/card_asset_cache/card_image_uploads
├── studio.initialized   # 原有数据库初始化保护标记
└── assets/
    ├── <sha256>.png     # 原始 PNG 或解析后的 PNG 资源
    ├── <sha256>.jpg     # JPEG 头像缓存
    └── <sha256>.webp    # WebP 头像缓存
```

原有 v1 / v2 / v3 / v4 数据库会迁移到 v5，保留权限、人工锁、普通人格备份和审计。卡片当前内容和新增定版快照在同一个 SQLite 事务内提交。旧配置 `backup_keep_count` / `backup_keep_days` 仅清理普通人格备份，不清理卡片快照。资源目前不自动回收，以保留历史恢复能力。

AstrBot 核心数据库继续保存人格，插件通过 PersonaManager 写入，不直接修改核心表。保存流程先提交卡片，再同步核心运行副本：失败时卡片仍保留，页面显示失败并可手动重试。重载不会自动覆盖核心或反向导入核心修改。归档只停用卡片适配，保留核心人格、原图与快照；可以从快照恢复。解除绑定保留两边内容。

同步记录核心记录身份和上次管理的提示词/预设对话。核心内容有外部修改时停止覆盖，页面可以比较“当前”与“目标”，明确覆盖操作携带当时读取的核心状态令牌；若再次改变则要求刷新。同名人格被删除重建时原卡保持冲突，不自动接管；解除原绑定后，新记录可在刷新时转换为独立卡片。外部工具/技能调整不触发提示词冲突。

插件锁只约束本插件；检查后到核心写入之间仍存在其他进程并发写入的窗口，跨数据库没有原子事务。编辑同一人格时应避免其他入口同时保存。

## 权限与 API

聊天入口沿用真实事件、白名单、归属和群聊配置。模型只能编辑自己有权管理的卡片，不提供锁定、解锁、绑定或冲突覆盖工具。卡片锁只能在插件页面由真人修改；核心 `/fs lock <人格ID>` 同样阻止卡片写入。旧 `persona_update`、`persona_delete` 和普通备份恢复不能绕过活跃卡片管理，需用卡片接口或先解除绑定。

插件页面使用核心已认证的 WebUI 用户名，拥有管理权限；不信任正文或查询中的用户身份。导入预览绑定该用户，30 分钟后过期；重复提交同一预览的新建请求返回已创建的卡片，避免重复新建。

新增 8 个模型工具：

| 工具 | 参数 |
| --- | --- |
| `character_list` | 可选 `offset` / `limit` / `deleted` |
| `character_get` | `card_id` |
| `character_create` | 完整 `card`；可选 `options` / `bind` |
| `character_update` | `card_id` / `expected_revision`，以及完整 `card` 或局部 `data`、可选 `options` |
| `character_archive` | `card_id` / `expected_revision` |
| `character_snapshot_list` | `card_id` |
| `character_snapshot_get` | `card_id` / `snapshot_id` |
| `character_snapshot_restore` | `card_id` / `snapshot_id` / `expected_revision` |

页面 API 位于核心认证路由 `/api/v1/plugins/extensions/astrbot_plugin_fusheng_scroll/`（旧路由 `/api/plug/astrbot_plugin_fusheng_scroll/` 仍兼容）：`GET cards/card/avatar/card-image/export`、`POST upload-card-image/upload-avatar`（multipart `file`，返回待保存的 `upload_id` 与预览）、`POST import`（multipart `file`）、`POST action`（`{action,payload}`）。旧插件标识 `astrbot_plugin_persona_studio` 的对应 API 路径也保留，使用同样的认证和数据。页面桥接直接使用 `cards` / `action` 等相对端点名，核心自动加入当前插件作用域。`GET cards` 与 `character_list` 会自动纳入可访问的未管理人格；`conversion_errors` 返回无法转换的记录。`update` 的 `images` 可传 `card_image` / `avatar` 上传标识；`avatar: "ccdefault"` 改为跟随底图，提交时与其他编辑一起保存。`preview` 不保存数据；`action` 另支持 `sync`、`bind`、`unbind`、`lock`。

`action: "worldbook_preview"` 的 `payload` 为 `{card,prompt,history?,username?}`：`card` 是完整草稿，`prompt` 为测试消息（最多 32000 字符）；`history` 为从旧到新的字符串列表（最多 50 条、共 32000 字符）；`username` 默认“访客”，最多 255 字符。返回 `entries` 逐条原因、`before` / `after` 实际注入片段、`used_chars` / `max_chars`、扫描数量与兼容说明；只读，不保存草稿。

JSON 最大 2 MiB，上传 PNG 最大 20 MiB，图片边长不超过 8192 且像素不超过 3200 万；PNG 数据块校验与压缩文本大小检查在导入时执行。卡片文本仍受现有提示词/示例对话字符配额限制。
